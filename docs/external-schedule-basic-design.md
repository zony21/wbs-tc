# 社外向けスケジュール出力機能 基本設計

## 1. 文書概要

### 1.1 目的

WBSで管理している案件・フェーズ・タスク情報を基に、先方へ提示するためのスケジュール資料を生成する機能を追加する。

本機能では、社内管理用タスクを含むWBSをそのまま外部公開せず、**社外出力対象として指定されたタスクのみ**を抽出し、担当者情報を除外した縦型スケジュールとしてプレビューおよびPDF出力できるようにする。

### 1.2 対象機能

- タスクへの社外出力対象設定
- タスクへの予定工数入力
- 社外向けスケジュールプレビュー
- 縦型カレンダー表示
- PDF出力
- 出力対象タスクの抽出・除外
- 担当者情報の出力抑止

### 1.3 対象外

現時点の要件に含まれないため、以下は本設計の対象外とする。

- PDFのメール送信
- 顧客ごとの公開権限管理
- 出力履歴管理
- PDFへの電子署名
- 祝日マスタ管理
- 実績工数の出力
- 担当者の出力

---

## 2. 要件整理

| No | 要件 | 基本設計での対応 |
|---|---|---|
| R-01 | スケジュールプレビュー機能が必要 | 社外向けスケジュール専用プレビュー画面を追加する |
| R-02 | PDF出力機能が必要 | プレビュー内容を基にPDFを生成する |
| R-03 | 除外したタスクはスケジュールに載せない | タスクに社外出力対象フラグを追加し、対象外タスクは抽出段階で除外する |
| R-04 | 社内のみのタスクもWBSで管理する | WBS上のタスク管理は変更せず、外部出力時のみフィルタする |
| R-05 | 担当者は出力しない | プレビュー／PDF用データモデルに担当者情報を含めない |
| R-06 | 縦型カレンダーで完了時期が分かるようにする | 日付を縦軸として開始日～期限を視覚化する |
| R-07 | 各タスクがどれほどで終わるか工数を出したい | タスクに予定工数（時間）を追加する |

---

## 3. 現行仕様との関係

### 3.1 現行WBS階層

現行のWBSは以下の階層で管理する。

```text
案件
 └ 大日程フェーズ
     └ 親タスク
         └ 子タスク
```

社外向けスケジュールでも案件・フェーズ・タスクの関係を利用する。

### 3.2 現行タスク項目

現行タスクは以下の情報を保持している。

- タスクID
- フェーズID
- 親タスクID
- タスク名称
- カテゴリ
- 開始日
- 期限
- 進捗率
- 担当者

予定工数および社外出力対象フラグは現行データに存在しないため、本機能で追加する。

### 4.1 機能一覧

| 機能ID | 機能名 | 概要 |
|---|---|---|
| ES-01 | 社外出力対象設定 | タスク単位で外部スケジュールへの掲載可否を設定する |

| ES-05 | 縦型カレンダー表示 | 日付を縦方向に配置し、各タスクの期間を表示する |
| ES-06 | PDF出力 | プレビュー対象データをPDF化する |

## 5. 画面設計

## 5.1 WBS管理画面

### 5.1.1 追加操作

WBS管理画面に以下の操作を追加する。

```text
[スケジュールプレビュー]
```

押下すると、現在選択中の案件を対象として社外向けスケジュールプレビュー画面を表示する。

### 5.1.2 既存WBSへの影響

WBS上では社内用タスクも従来どおり表示・編集可能とする。

社外出力対象外であることをWBS一覧上で識別表示するかどうかは未確定とする。

---

## 5.2 タスク登録・編集画面

### 5.2.1 追加項目

既存のタスク登録・編集フォームに以下を追加する。

| 項目 | 入力形式 | 必須 | 説明 |
|---|---|---:|---|
| 予定工数 | 数値入力 | 条件付き | タスク完了までに必要な予定作業時間 |
| 社外スケジュール出力対象 | チェックボックス | - | ONの場合のみ社外向けスケジュールの候補とする |

表示イメージ：

```text
予定工数
[ 16 ] 時間

□ 社外スケジュールに掲載する
```

### 5.2.2 予定工数の単位

DBおよび内部データでは**時間（hour）**で保持する。

開始日～期限の期間から予定工数を自動推定しない。

理由：同じ5日間のタスクでも、40時間作業する場合と8時間のみ作業する場合があり、期間だけから工数を確定できないため。

### 5.2.3 入力制約

予定工数は0未満を許可しない。

社外出力対象タスクで予定工数を必須にするかどうかは、未確定事項として扱う。

---

## 5.3 スケジュールプレビュー画面

### 5.3.1 画面目的

PDF生成前に、実際に外部へ提示する情報のみを確認する。

### 5.3.2 表示項目

プレビューに表示する情報は以下とする。

- 案件名
- 対象期間
- フェーズ名
- タスク名
- 開始日
- 期限
- 予定工数

### 5.3.3 表示禁止項目

以下はプレビューおよびPDFに表示しない。

- 担当者
- タスク担当者一覧
- 日報情報
- 社外出力対象外タスク

タスクID、カテゴリ、進捗率を社外資料へ表示するかは要件未確定のため、本設計では表示対象外とする。

### 5.3.4 操作

```text
[WBSへ戻る]    [PDF出力]
```

PDF出力ボタンは、プレビューと同じ出力対象データを利用する。

## 6. 縦型カレンダー設計

### 6.1 基本方針

横軸を日付にする一般的なガントチャートではなく、**日付を上から下へ進む縦軸**として表示する。

利用者が上から順に確認することで、以下を把握できることを目的とする。

- タスクがいつ始まるか
- タスクがいつまで続くか
- いつ完了予定か
- タスクごとの予定工数

### 6.2 表示イメージ

```text
○○案件 スケジュール

10/01（木） │ 基本設計
             │ ┌ 画面設計
             │ │ 予定工数 16h
10/02（金） │ │
10/03（土） │ │
10/04（日） │ └ 完了予定
             │
10/05（月） │ ┌ DB設計
             │ │ 予定工数 24h
10/06（火） │ │
10/07（水） │ └ 完了予定
```

実際の画面では、タスクを開始日から期限まで縦方向に連続するブロックとして描画する。

### 6.3 並び順

出力対象タスクは以下の順で整理する。

1. 開始日昇順
2. 同一開始日の場合は期限昇順
3. 同一期間の場合はWBS上の階層順

### 6.4 フェーズ表示

出力対象タスクが1件以上存在するフェーズのみ表示する。

フェーズ内の全タスクが社外出力対象外の場合、そのフェーズも出力しない。

### 6.5 親子タスク

親タスク・子タスクはそれぞれ独立したタスクとして社外出力対象を判定する。

以下のケースは未確定事項として扱う。

- 親タスクが非公開、子タスクが公開の場合の見せ方
- 親タスクのみ公開し、子タスクを非公開にした場合の表示粒度

社内用タスク名が外部資料へ漏れないことを最優先とし、非公開タスク名称を補完表示してはならない。

### 6.6 対象期間

対象期間の決定方式は未確定とする。

設計候補：

- 案A：案件の開始日～終了日を使用
- 案B：出力対象タスクの最小開始日～最大期限を使用
- 案C：プレビュー画面で利用者が期間指定

## 7. PDF出力設計

### 7.1 出力内容

PDFには以下を出力する。

- 案件名
- 対象期間
- 出力日
- 縦型カレンダー
- フェーズ名
- タスク名
- タスク開始日
- タスク期限
- 予定工数

### 7.2 非出力情報

以下はPDFへ含めない。

- 担当者
- 社外出力対象外タスク
- 日報
- 内部用の担当者配列

### 7.3 プレビューとの整合

プレビューとPDFで使用する抽出条件を分けない。

共通のスケジュール出力用データモデルを生成し、プレビュー・PDFの両方が同じデータモデルを参照する。

```text
WBSデータ
   ↓
社外公開フィルタ
   ↓
ExternalScheduleViewModel
   ├─ プレビュー
   └─ PDF
```

これにより、プレビューでは見えていない社内タスクがPDFだけに出力されることを防止する。

### 7.4 改ページ

対象期間が1ページに収まらない場合は複数ページに分割する。

改ページ単位、用紙サイズ、縦横方向は未確定事項とする。

設計候補としてA4縦を想定するが、要件確定までは固定しない。

## 8. データ設計

## 8.1 WbsTask拡張

現行の `WbsTask` に以下を追加する。

```ts
interface WbsTask {
  id: string
  sectionId: string
  parentId: string | null
  name: string
  category: string
  startDate: string
  dueDate: string
  progress: number
  assignees: string[]

  // 追加
  plannedEffortHours: number | null
  includeInExternalSchedule: boolean
}
```

### 8.1.1 plannedEffortHours

| 項目 | 内容 |
|---|---|
| 論理名 | 予定工数 |
| 型 | number / DBではREAL |
| 単位 | 時間 |
| NULL | 許可 |
| 制約 | 0以上 |

### 8.1.2 includeInExternalSchedule

| 項目 | 内容 |
|---|---|
| 論理名 | 社外スケジュール出力対象 |
| 型 | boolean / DBではINTEGER |
| 値 | 0:対象外 / 1:対象 |
| NULL | 不可 |

既存タスクに対する初期値は未確定事項とする。

社内タスクの誤公開防止の観点では、既存タスク・新規タスクともに初期値を `false` とする案を推奨する。

---

## 8.2 SQLite変更

`tasks` テーブルに以下のカラムを追加する。

```sql
planned_effort_hours REAL,
include_in_external_schedule INTEGER NOT NULL DEFAULT 0
```

### 8.2.1 既存DB移行

既存SQLiteファイルをそのまま利用できるよう、起動時に `PRAGMA table_info(tasks)` でカラム存在確認を行う。

存在しない場合のみ `ALTER TABLE` を実行する。

```sql
ALTER TABLE tasks ADD COLUMN planned_effort_hours REAL;
ALTER TABLE tasks ADD COLUMN include_in_external_schedule INTEGER NOT NULL DEFAULT 0;
```

DBファイルの削除・再作成を前提としない。

### 8.2.2 保存・読込処理

以下を修正対象とする。

- `insertTask`
- `readState()` 内のtasks取得SQL
- `replaceState()` のtasks保存
- `normalizeState()`
- クライアント側 `WbsTask` 型
- localStorage旧データの正規化

既存localStorageに追加項目がない場合は、未定義値を補完する必要がある。

---

## 9. 社外スケジュール用データモデル

担当者情報を誤って表示しないため、WBSの `WbsTask` をそのままPDFレンダラーへ渡さない。

社外出力専用データ型を定義する。

```ts
interface ExternalScheduleTask {
  id: string
  sectionId: string
  parentId: string | null
  name: string
  startDate: string
  dueDate: string
  plannedEffortHours: number | null
}

interface ExternalScheduleSection {
  id: string
  name: string
  tasks: ExternalScheduleTask[]
}

interface ExternalScheduleViewModel {
  projectName: string
  startDate: string
  endDate: string
  generatedAt: string
  sections: ExternalScheduleSection[]
}
```

**assigneesはこのデータ型に持たせない。**

## 10. データ抽出処理

### 10.1 処理概要

```text
選択中案件取得
 ↓
案件配下フェーズ取得
 ↓
案件配下タスク取得
 ↓
includeInExternalSchedule = true のみ抽出
 ↓
担当者・内部情報を除外
 ↓
フェーズ単位に再構成
 ↓
期間順にソート
 ↓
ExternalScheduleViewModel生成
 ↓
プレビュー / PDF
```

### 10.2 除外条件

以下に該当するタスクはプレビューおよびPDFに含めない。

```text
includeInExternalSchedule !== true
```

画面上で非表示にするだけではなく、**出力用データ生成段階で除外する**。

## 11. バリデーション・エラー処理

### 11.1 出力対象なし

対象案件に社外出力対象タスクが1件もない場合：

```text
社外スケジュールに出力するタスクがありません。
WBSのタスク編集から出力対象を設定してください。
```

PDF出力は実行しない。

### 11.2 予定工数未入力

社外出力対象タスクに予定工数が未入力の場合の扱いは未確定とする。

候補：

- 案A：プレビュー・PDF出力を不可とする
- 案B：`工数未設定` と表示して出力を許可する
- 案C：工数表示のみ空欄とする

「各タスクがどれほどで終わるのか工数を出したい」という要件を厳密に満たす場合は案Aを推奨する。

### 11.3 不正な期間

開始日 > 期限となるデータは出力対象としない、またはエラー表示する。

既存タスク登録側の期間チェックに加えて、出力直前にも防御的に検証する。

## 12. 情報公開制御

### 12.1 担当者情報

担当者はプレビュー・PDFに表示しない。

表示コンポーネント側で単に非表示にするだけではなく、`ExternalScheduleViewModel` に担当者情報そのものを渡さない。

### 12.2 社内タスク

社外出力対象外タスクは以下のすべてから除外する。

- プレビュー一覧
- 縦型カレンダー
- PDF本文
- PDF生成用一時データ

### 12.3 非公開親タスク

非公開親タスクの名称を、公開子タスクの階層補完のために自動出力してはならない。

親子表示ルールは別途確定する。

## 15. 受入条件

### AC-01 出力対象制御

- 社外出力対象ONのタスクがプレビューに表示されること
- 社外出力対象OFFのタスクがプレビューに表示されないこと
- OFFのタスクがPDFにも含まれないこと

### AC-02 担当者非表示

- プレビューに担当者が表示されないこと
- PDFに担当者が表示されないこと
- 社外出力用ViewModelに担当者情報が存在しないこと

### AC-03 期間表示

- タスク開始日が確認できること
- タスク期限が確認できること
- 縦方向の日付軸で終了予定日を確認できること

### AC-04 工数

- タスクに予定工数を登録できること
- 登録した予定工数がプレビューへ反映されること
- 登録した予定工数がPDFへ反映されること

### AC-05 PDF

- プレビュー対象とPDF対象のタスクが一致すること
- 長期間の場合もページ欠落なく出力できること
- 社外出力対象外タスクがPDFへ混入しないこと

### AC-06 既存データ

- 既存SQLite DBを削除せず起動できること
- 既存タスクを読み込めること
- 新規カラム追加後も既存の日報・WBS機能が利用できること

## 17. 実装優先順

基本設計上の実装順は以下を推奨する。

1. `WbsTask`／SQLiteへ予定工数・社外出力対象を追加
2. タスク登録・編集画面へ入力項目追加
3. 社外出力用ViewModel生成処理を実装
4. 出力対象フィルタ・バリデーションを実装
5. 縦型カレンダープレビューを実装
6. PDF生成を実装
7. プレビューとPDFの一致確認
8. 社内タスク／担当者の漏洩がないことを受入テスト

---

## 18. 設計上の重要事項

本機能で最も重要な点は、**WBSの表示内容をそのままPDF化しないこと**である。

WBSには社内限定タスク・担当者情報が存在するため、PDF生成前に必ず社外公開専用データへ変換する。

```text
内部WBSデータ
      ↓
公開可否判定
      ↓
社外出力専用データ
      ↓
プレビュー / PDF
```

この境界を設けることで、UI上の表示ミスだけでなく、PDF生成処理への社内情報混入も防止する。
